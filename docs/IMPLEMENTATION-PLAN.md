# 实施路线与验收

版本：0.4 · 2026-10-30 · 目标设计

本轮交付为架构文档。下列阶段均为后续开发计划，不代表已部署的能力，也不把现有 58 项原型测试当作后端与沙箱验收结果。

## 方向已确定与待验证项

| 项目 | 当前决定 | 需要的证据 |
| --- | --- | --- |
| Harness | Claude Agent SDK，运行在 E2B | 单次任务、工具、事件、取消、会话续跑验证 |
| 语言分工 | React + TypeScript；API／Workers／Runner 用 Python 3.12+ | API 契约生成、SDK 安装和 E2B 模板兼容 |
| 通信 | REST + SSE；Runner NDJSON + 控制文件 | 分片、断线、重复事件、取消竞态验证 |
| 业务存储 | PostgreSQL + pgvector；S3 兼容对象存储 | 隔离、事务、向量权限过滤和对象授权验证 |
| 异步调度 | Redis Streams + PostgreSQL outbox | 消费恢复、重复投递、租约、fencing 和重放验证 |
| 会话隔离 | 一活动 Session 一沙箱，Session 内 Attempt 串行 | 并发租户、工作区隔离、超时清理验证 |
| 模型、Embedding、Rerank | Harness 与这些 provider 分开配置 | 可用模型、区域、质量、成本及企业要求评估 |
| 固定版本 | 暂不写猜测的版本号 | PoC 后锁 SDK／CLI／E2B SDK／模板 digest，并归档兼容矩阵 |
| 商业运营 | 延续 SaaS 产品基础的用量／配额方向 | 套餐、席位、计费主体、区域和保留期进一步确认 |

## 阶段 0：最小执行 PoC

范围：单个测试企业、一个任务、无真实平台写操作。构建 E2B 模板，安装 Python Runner、锁定 Claude Agent SDK／CLI，验证普通 e2b SDK 的命令、文件和进程能力。提供临时测试配置，不写入仓库或前端。

验收：

- 按 [文件系统规范](SANDBOX-FILESYSTEM.md) 验证 `/mnt/session` 目录、SDK cwd 与成果出口；E2B beta 卷只作为可选 RW 检查点，不承载需要只读保护的资料。

- 从服务端创建沙箱并运行任务，持续获得可解析的事件，生成一份文件并上传对象存储。
- Runner 用户无法修改只读知识目录、运行时代码或访问控制面凭证；不能读取另一 Session 的数据。
- 验证 SDK cancel／interrupt 及终结消息排空、超时强制停止、模型额度或预算错误，不把异常报告为成功。
- 验证 NDJSON 分片、 stderr 脱敏、控制文件投递、丢失心跳和进程退出。
- 保存会话与工作区，验证同沙箱续跑、暂停恢复、重新创建环境后的恢复；材料缺失时明确降级为重新开始。
- 验证模型网关与 SDK 的兼容性；确认 API 认证、地区和产品服务条件。

退出条件：输出 SDK／CLI／模板兼容矩阵和 PoC 实测记录；只读目录、模型出口或取消不可证明时，先调整运行策略再进入下一阶段。

## 阶段 1：SaaS 控制面

实现 Tenant、User、Membership、Department、预设 Role、Project、AgentVersion、ResourceGrant；接入登录、数据库和对象存储。建立 migrations、审计、密钥引用和 API schema。React 外壳接企业成员管理与当前租户上下文。

验收重点：两个租户的同名用户和同名项目不能串数据；直接猜测 ID、签名 URL、队列消息和向量查询不能绕过授权。管理员与资源阅读范围分开，停用成员撤销会话；所有权转移受事务保护；连接池切换上下文后不残留上个租户。

退出条件：账号、成员与资源权限在 API／Worker／Gateway 一致生效，不能靠 localStorage 的角色决定访问权。

## 阶段 2：真实任务与成果闭环

实现 Task／Attempt／Outbox／TaskEvent、Task Worker、Runner Adapter、SSE、Artifact 与版本存储。按当前原型的任务列表和详情逐页替换 React 界面，保留中文默认与英文切换。配额先覆盖并发数、执行时长与模型预算，记录可核对用量。

验收重点：任务幂等、排队与串行、工具事件、取消竞态、Worker 宕机接管、上传失败、回放补发、过期 cursor、租约 fencing。SDK 结束但产物未入库时不能显示交付成功。已完成任务再次打开无须重新运行模型。

退出条件：可重复完成“成员发起 → Agent 执行 → 成果持久化 → 人工确认”，失败可解释、可恢复，统计来自真实事件。

## 阶段 3：知识与 Wiki

实现文件上传、扫描、解析、版本化分块、向量检索和引用，按需引入 Rerank。先完成知识检索与快照，再引入带引用的 Wiki 草稿和审阅发布。Artifact Editor 采用乐观并发和新版本写入，格式优先级按实际业务场景确定。

验收重点：知识权限在召回前过滤；增量索引幂等；索引未完成不切换 published revision；删除与撤销影响缓存和活动执行；上传文件中的提示内容不能改系统配置或工具策略。

退出条件：任务可基于有权限的企业资料生成可溯源结果；Wiki 生成不会越权覆盖权威知识。

## 阶段 4：飞书与企业微信真实接入

按 [生态调研](../workmates-prototype/docs/ECOSYSTEM-INTEGRATION-RESEARCH.md) 分开实现应用机器人、智能机器人、自建应用、Webhook 和业务授权。统一接入任务服务，独立实现事件认证、身份映射、触发规则、确认响应和渠道投递。

验收重点：绑定版本和原会话快照不可被新配置覆盖；同一伙伴跨平台不混用消息、身份或成果；回调重复不重复建任务；停用绑定阻断回传；回传重试不重新执行 Claude；平台超时且发送结果不明进入 unknown，不承诺 exactly-once。

退出条件：至少一个真实业务场景贯通“平台收消息 → WorkX 执行 → 工作台进度 → 原渠道结果”，之后逐种扩大接入方式。

## 阶段 5：运营与扩展

按试点结果完善订阅计费、席位、成本归集、保留期、审计导出、灾难恢复、SSO／组织同步，以及多伙伴协作。多智能体和会话 fork 单独设计权限、工作区和成本边界，不因 SDK 支持就默认对所有成员开放。

## 核心故障验收矩阵

| 注入情境 | 必须观察到的结果 |
| --- | --- |
| 浏览器断开后重连 | 补发事件并去重，任务执行次数不增加 |
| Worker 接到重复队列消息 | 只有一个有效租约，不能双重发布成果 |
| 旧 Worker 在新 Attempt 启动后恢复 | fencing 失效，不能提交状态或执行 Gateway 写操作 |
| SDK 崩溃／预算耗尽 | 有明确失败原因，保留已持久结果，不伪装成功 |
| 取消与 success 同时到达 | 通过数据库版本仲裁，状态不来回变化 |
| E2B 超时／被销毁 | 业务状态仍存在，可按可用恢复包决定恢复或重新开始 |
| 成果上传或数据库登记失败 | 重试采集或登记，不重复生成和覆盖已发布版本 |
| 平台返回超时 | 核对回执或进入 unknown，不盲目重复外发 |
| 成员或知识权限撤销 | 新调用被拒，必要时终止含敏感快照的执行 |
| 跨租户 ID／路径／向量请求 | 在各层拒绝并记录审计，不泄露另一企业存在与内容 |

首次端到端测试使用专用测试账号和测试群；部署密钥和测试数据单独配置。生产上线前补充明确的性能目标、备份恢复目标、告警阈值和成本预算，用实际试点数据确定数值。

## 凭证与知识选型验收增补

- [凭证层](CREDENTIALS-AND-CONNECTORS.md)：验证 SSO 与业务授权分离，飞书用户／应用身份、CLI 集中凭证扩展、无桌面执行、Refresh Token 并发轮换、撤销、短期 Gateway 票据和日志脱敏。Nango 按实际许可和自托管功能矩阵验证，不假设免费版带完整 MCP／工具／审计功能。
- [Knowledge](KNOWLEDGE-PIPELINE.md)：Tika 与按需 OCR 验证中文 PDF／Office／扫描件及可靠引用；Meilisearch 与 pgvector 基线使用同一语料比较关键词、语义、过滤、ACL 撤销、延迟与费用，再选择一个主检索 Provider。
- [凭证落地方案](CREDENTIAL-SOLUTION.md#分期)：P0 Vault、manifest、企业共享 A 类凭证、Gateway 注入与任务票据；P1 个人 OAuth、`needs_auth` 挂起恢复、飞书／企业微信交换；P2 出口占位符替换、lark-cli sidecar relay、受控 Worker、Nango 长尾与企业 SSO。P0 验收以“沙箱内读不出任何真实凭证”为首要标准。
- 后续只有选型 PoC 通过才新增依赖和部署服务。本轮仅调研及调整文档，未安装上述中间件、处理真实企业文档或读取外部连接凭证。

异构接入门槛：按 [Nango 引入评审](NANGO-ADOPTION.md) 分别验证 none、静态 Header、OAuth DCR／CIMD／固定 Client、stdio；按 [Skill 运行契约](SKILL-RUNTIME-CONTRACT.md) 验证独立 env／`.env`／证书文件。同一供应商能力可用不等于全部连接模式已验证。Meilisearch PoC 必须验证引擎自动 Embedding 和真实向量查询，不只测试关键词；业务切块仍由 WorkX 负责。
