# WorkX 高仿真交互原型

WorkX 是面向业务场景、可扩展企业工具生态的团队 AI 工作台。成员与智能伙伴围绕项目共享背景、安排分工并确认成果；生态接入按“平台 → 接入方式 → 关联伙伴 → 授权能力”配置，同一伙伴可以绑定飞书、企业微信等多个渠道。业务场景先提供预留入口和草稿记录。

当前交互原型以浏览器中打开的 Doubao Workmates 工作台为视觉参考，复刻侧栏导航、伙伴卡片、快捷任务、任务列表与新建任务布局。使用通用演示数据与本地 SVG 头像。

## 启动

需要 Node.js 20+，无需安装依赖。

```sh
cd workmates-prototype
npm run dev
```

打开 [本地工作台](http://127.0.0.1:4173/)。语法检查：`npm run check`。

## 体验生态接入

1. 打开 [生态接入](http://127.0.0.1:4173/#ecosystem)，新增绑定并选择飞书或企业微信。
2. 选择平台对应的接入方式；企业微信智能机器人还可选择 WebSocket 长连接或 HTTP 回调模式。
3. 关联一个已有智能伙伴，为绑定命名，再查看和选择该方式允许申请的能力。
4. 保存绑定后进入“接入配置”，按“参数 → 授权步骤 → 连接测试”完成平台设置；也可从绑定列表或伙伴详情重新进入。
5. 在参数页选择对应的机器人连接方式，填写演示参数或填入示例参数；按授权指引逐项确认平台设置。飞书应用机器人、企业微信智能机器人、自建应用和群 Webhook 展示不同的参数与指引。
6. 在连接测试中选择模拟成功、凭证错误、权限缺失或超时，查看进度和处理建议；可以取消、修正配置或重试。可显式保存未完成的配置草稿或模拟测试结果；点击下一步或开始测试时会检查必填项与步骤确认。
7. 返回列表预览、编辑、暂停、恢复或删除单条绑定。可以继续为同一伙伴添加另一平台或另一接入方式，已有记录互不覆盖。
8. 在 [伙伴详情](http://127.0.0.1:4173/#detail/a1) 查看当前伙伴的绑定，或带着该伙伴选择新增绑定；[业务场景](http://127.0.0.1:4173/#scenarios) 仍仅提供草稿管理。

“授权能力”步骤只记录拟申请的范围，状态为待真实授权。“消息交互”与“业务工具”分组呈现；群 Webhook 只用于通知输出，不提供双向对话或业务工具授权。授权清单是本地流程确认，连接测试明确为模拟，不提交真实授权、验证平台凭据或外发消息。

参数页可用示例值体验。App Secret、Bot Secret、Token、EncodingAESKey、签名密钥及完整 Webhook URL 仅保留在当前配置弹窗内存中，保存或关闭即清除，不写入 localStorage；重新测试时需重新填写。保存的是非敏感配置、授权步骤确认和模拟测试结果。回调地址使用 `example.invalid` 演示地址，不能拿到平台后台进行真实校验。

## 体验机器人消息到结果回传

1. 在生态接入中选用飞书应用机器人、企业微信智能机器人或企业微信自建应用消息接入，完成并保存一次模拟连接成功；保持绑定启用。
2. 打开 [消息工作台](http://127.0.0.1:4173/#inbox)，模拟接收平台消息，选择绑定并填写发送人、来源会话和消息内容，可关联项目。
3. 提交后由该绑定关联的伙伴创建任务；在消息工作台、首页任务列表或任务详情查看消息来源和执行进度。任务保留收到消息时的来源与伙伴信息。
4. 在成功情境中查看演示成果和回传记录；选择执行失败或回传失败情境，体验对应的修正与重试。执行重试沿用原任务，回传重试复用已有成果。
5. 在任务详情重放同一消息，核对不会重复创建任务或成果；运行时可取消流程，已产生的成果仍会保留，之后按阶段重试。关闭未提交的消息弹窗仅取消草稿。
6. 使用同一伙伴的飞书和企业微信绑定分别提交消息，核对任务来源和回传会话各自独立。暂停、删除或改动绑定后，旧任务不能自动改投其他渠道。

当前是本地闭环演示，消息由体验者手动填写，伙伴输出为模板内容，回传不调用外部平台。群 Webhook 和业务 API 不提供收消息入口。运行中刷新不会伪造已回传，需从中断状态显式恢复。具体触发限制、异常状态和验收范围见功能清单。

## 可体验的流程

- Home：伙伴卡片、快捷任务、消息任务概览、任务搜索和筛选、置顶、重命名、归档和恢复。
- 消息工作台：模拟平台收消息、关联伙伴执行、进度与成果、同会话结果回传，以及执行或回传失败后的重试。
- 空间制 SaaS：个人／组织切换、创建组织、独立个人设置与组织管理；演示邀请、成员角色、数据共享范围和连接归属登记。
- 生态接入：按平台分别配置多个绑定，体验四步绑定、平台参数、授权步骤、模拟连接测试、失败修正，以及预览、编辑、暂停、恢复和删除确认。
- 业务场景：预留入口、空状态与草稿创建、编辑、删除；不预置具体业务案例。
- New Task：伙伴与项目选择、能力和模型选项、附件文件名、发送任务、演示结果及追问。
- Workmate Details：指令、能力、工作上下文、基本信息编辑，以及当前伙伴的生态绑定列表和新增入口。
- Automations：创建周期任务配置、暂停与恢复演示状态。
- Projects：创建项目、任务看板、成员与伙伴分工、共享背景、项目成果、确认和撤回确认；异常任务进入需处理列。
- Library：类型筛选、文件预览、Markdown 下载。
- Hub / Code：伙伴检索与分类、编程任务入口。
- 全局搜索：⌘/Ctrl K；发送任务：⌘/Ctrl Enter；关闭弹窗：Esc。

演示数据按空间保存在浏览器 localStorage（`workx-spaces-v1`）中；旧 `workmates-prototype-v1` 只作迁移输入保留。成员、项目分工、共享背景、成果确认、生态配置、渠道消息任务与回传记录、场景草稿均为本地状态；不邀请真实成员，不跨账号同步，也不连接真实飞书、企业微信、AI 模型或定时调度服务。附件仅记录文件名；模型和能力为演示配置；文档下载为 Markdown。

协作方向参考用户指定的 [扣子团队版说明](https://docs.coze.cn/about-coze-team)，本轮具体实现项目、成员、共享伙伴和成果确认的本地交互。

## 文件

`dist/` 是可直接静态托管的成品；`app.js` 处理页面和交互，`data.js` 提供演示数据，`secondary.js` 提供辅助页面，`style.css` 与 `secondary.css` 定义样式，`icons.js` 和 `assets/` 提供图标头像。

`team.js` / `team.css` 提供团队与项目协作；`ecosystem.js` / `ecosystem.css` 提供生态绑定向导、管理及场景草稿，`ecosystem-model.js` 定义平台、接入方式、能力范围与旧配置迁移；`workspace.css` 衔接导航、首页和任务详情。各模块配套双语文案文件。

`connection.js` / `connection.css` 提供平台参数、授权步骤和模拟测试面板；`connection-model.js` 定义不同接入方式的字段、校验、授权清单和持久化白名单。

`channel.js` / `channel.css` 提供消息工作台、渠道任务过程和模拟回传；`channel-model.js` 管理来源对应、任务与成果、失败重试、取消及刷新恢复，配套双语文案记录来源、执行与交付状态。

## 验证

初始原型已通过 JavaScript 语法检查，以及浏览器中的任务提交、伙伴创建与详情、自动化创建与暂停、全局搜索、项目任务关联、文件预览流程。已检查桌面和 390px 移动宽度，控制台未发现运行错误。

当前空间制 SaaS 迭代通过 JavaScript 语法检查及 73 项自动化行为回归，覆盖旧数据迁移、个人／组织独立资源、创建组织、邀请校验／接受／撤销／过期、连接元数据白名单、资源共享、草稿与后台回调归属。浏览器已走查独立设置导航、空间切换、组织创建、演示邀请、连接登记及指定成员共享，并检查中英界面和 390px 窄屏布局；所查页面没有浏览器运行错误。完整复验执行 `npm run check`、`npm test`；精确测试结果在本轮交付说明报告。

## 语言

界面支持 English（默认）和简体中文，在侧栏底部的语言入口切换，接入配置面板内也可切换。语言选择单独保存在 `workx-locale`，刷新后继续使用；不会改写任务、项目或伙伴数据。切换时保留任务草稿、编程草稿、项目和能力选择，以及生态向导、接入配置当前步骤和填写内容。自定义名称与任务正文保持输入时的语言；未保存草稿不承诺刷新恢复。

`dist/i18n.js` 负责语言选择和参数插值，`messages-main.js`、`messages-actions.js`、`messages-secondary.js` 保存双语文案。语言列表只包含 `zh-CN` 和 `en`。

执行 `npm test` 可检查语言默认值与持久化、翻译完整性、各页面双语渲染、草稿保留和表单内部值稳定性。测试使用浏览器 I/O 替身，不代替浏览器视觉验收。早期双语迭代未做浏览器视觉复验；空间制 SaaS 迭代已另行进行浏览器走查。

## 体验空间制 SaaS

1. 侧栏底部账号菜单或顶部当前空间栏，切换个人／WorkX 组织。旧记录保留在原 WorkX 组织；个人初始没有任务、项目、文件或连接。
2. 菜单选择创建组织，填写名称；新 organization 默认仅本人 owner，不迁移个人资源。固定内置伙伴为示例。
3. 组织管理采用独立左侧导航：空间信息、成员与邀请、角色与权限、数据与共享、连接与凭证、使用情况、活动记录。
4. 成员页邀请邮箱并选择角色，创建本地演示邀请；可撤销或演示接受。7 天到期，接受仅执行一次，不发送邮件、不登录真实受邀人。
5. 数据页按分类查看资源所属空间与所有者，可配置本空间共享范围；部门不做权限继承，任务负责人也不等于资源所有者。
6. 连接页区分成员私有／组织服务连接，记录认证类别和伙伴关联；不输入真实 Secret、Token 或 .env，不代表已授权。机器人渠道配置仍在生态接入。
7. 账号菜单的个人设置是独立页面：语言、提醒、显示名称、我的空间。偏好属于全局账号，与当前组织策略分开。

普通草稿按空间在当前标签页内存保留，刷新不恢复；切换关闭敏感表单并清除临时参数。后台演示任务完成仍更新原空间。当前是单浏览器演示，没有真实登录、数据库隔离、跨账号同步或多标签页并发编辑同步。

`spaces-model.js` 管理独立空间数据、组织、邀请、连接与共享元数据；`spaces.js`／`spaces.css` 提供菜单、设置导航和流程，文案在 `messages-spaces.js`。产品清单为 0.9；详细规则见 [SaaS 产品设计](docs/SAAS-FOUNDATION.md)、[租户规范](../docs/TENANCY-MODEL.md) 和 [凭证方案](../docs/CREDENTIAL-SOLUTION.md)。Nango 不引入，真实 Broker／Gateway 与授权恢复仍待建设。
