# WorkX 业务场景梳理

WorkX 将根据实际业务场景扩展工作台，并按需接入飞书、企业微信机器人及其他企业工具。本文用于后续访谈、需求整理和场景评审，与 [产品功能清单](PRODUCT-FEATURES.md) 一起维护。

目前已明确生态和场景扩展方向，具体业务场景尚未确定。以下提供录入结构，不预设已批准的场景、平台能力或排期。

原型现已提供“业务场景”入口，可以记录和编辑名称、问题、角色、输入、输出及生态需求等草稿。下文用于补齐完整业务定义；草稿尚不具备执行能力。

## 场景总表

每确认一个待调研场景新增一行，编号使用 SC-001、SC-002 等；“状态”依次记录待梳理、待验证、已确认、开发中、已可用。

| 场景编号与名称 | 使用角色与业务问题 | 触发方式 | 资料来源与生态依赖 | 目标成果及去向 | 成功标准 | 状态与优先级 |
| --- | --- | --- | --- | --- | --- | --- |
| 待录入 | 待梳理 | 待梳理 | 待确认 | 待梳理 | 待定义 | 待梳理；未排期 |

## 单个场景记录模板

| 字段 | 需要明确的内容 |
| --- | --- |
| 编号与名称 | 用业务目标命名，保持与总表、工作台入口和任务记录对应。 |
| 使用角色 | 谁发起、谁使用成果、是否有其他参与人。 |
| 业务问题 | 当前如何完成工作，耗时或错误发生在哪里，为什么需要改进。 |
| 触发条件与入口 | 由工作台手动发起、外部消息或事件触发，还是周期执行；具体方式待接入能力验证。 |
| 输入信息 | 用户必填项、选填项、所需文件和业务数据；哪些来自人工，哪些可通过连接取得。 |
| 处理步骤 | 从发起到完成的业务步骤，各步骤由用户、AI 或业务系统完成。 |
| AI 能力 | 各步骤需要 AI 完成什么工作，以及如何判断输出合格。 |
| 生态与接入方式 | 所需平台、机器人或其他连接方式；分别说明其承担任务入口、资料来源、操作工具还是结果去向。 |
| 前置条件 | 必需的连接、可用接口、资料范围及用户权限；哪些仍需选型或联调确认。 |
| 结果与去向 | 输出内容和格式，在 WorkX 的项目或文件库归集位置，以及是否需要回传外部渠道。 |
| 用户介入点 | 哪些输入需要补充、哪些业务步骤需要用户判断或确认。 |
| 异常处理 | 缺少资料、连接不可用、执行失败或结果回传失败时，用户如何继续；已产出内容如何保留。 |
| 成功标准 | 一组具体输入应得到什么成果；正确性、完整性、处理时效等按业务定义，不预设目标值。 |
| 工作台呈现 | 场景入口、输入表单、执行进度、待处理事项、成果卡片，以及重新使用方式。 |
| 频率与价值 | 使用频率、影响人数、现有成本和预期改进，作为排序依据。 |
| 范围与排期 | 首版包含哪些步骤，依赖什么能力，负责人、优先级和目标版本；未确认项保留待定。 |

## 接入能力验证记录

按每种实际选择的接入方式分别填写。飞书与企业微信机器人当前均未接入真实服务；下表是后续验证项，不表示任一平台已经支持全部能力。

| 待验证能力 | 需要记录的结论 |
| --- | --- |
| 消息输入与任务触发 | 是否支持所需入口，哪些事件可以成为任务，输入和会话如何对应。 |
| 结果发送与通知 | 是否支持目标接收方及所需消息格式，如何取得发送结果或识别失败。 |
| 文件与业务资料 | 可读取、接收或传出的资料类型、来源范围和限制。 |
| 用户与会话识别 | 能否满足场景所需的身份和会话对应关系，如何关联 WorkX 任务。 |
| 外部业务操作 | 场景需要调用哪些操作，实际接口是否可用，以及所需授权条件。 |
| 运行与连接条件 | 接入配置、部署条件、连接状态判断和恢复方式。 |

每项结论记录“支持、受限支持或不支持”，附选定接入方式的官方依据及联调结果；未验证时保留“待验证”。场景所需能力未满足时，先调整范围或方案，再确定排期。

## 场景进入工作台的流程

1. 记录业务问题、使用角色和预期成果。
2. 确认处理步骤，映射所需 AI 能力及生态连接。
3. 验证依赖能力，并确定首版范围与成功标准。
4. 将场景配置为工作台入口与任务模板，复用伙伴、项目、任务和成果管理。
5. 按真实输入验收完整流程，再依据使用反馈完善或增加场景。
