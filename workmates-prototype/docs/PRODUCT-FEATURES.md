# WorkX 产品功能清单

文档版本：0.7  
基准日期：2026 年 10 月 30 日  
适用对象：产品经理、设计、研发、测试  
对应版本：当前本地交互原型，访问地址 http://127.0.0.1:4173/

凭证与知识调研配套：[授权与 Connector 架构](../../docs/CREDENTIALS-AND-CONNECTORS.md)、[Tika／Meilisearch 选型](../../docs/KNOWLEDGE-PIPELINE.md)；均为目标设计与候选评测，当前原型仍使用演示连接和结果。

架构配套：[系统架构文档](../../docs/README.md) 已确定 E2B + Claude Agent SDK 的目标执行方向；以下功能状态仍以当前原型实际能力为准。

WorkX 是以企业 SaaS 为目标形态、面向业务场景、可扩展企业工具生态的团队 AI 工作台。成员与智能伙伴围绕项目共享背景、分工推进任务并确认成果。飞书与企业微信统一归入生态接入，工作台将随着业务场景的梳理持续丰富。

产品组织方式建议以业务场景和智能伙伴为入口，以任务为主线，将工作过程和交付成果归集到项目中。本清单用于确定功能范围、拆分需求和制定验收标准。

当前版本可以验证页面结构和本地操作流程。AI 回答、定时执行、飞书连接等尚未接入真实服务，因此不能将可点击的界面等同于已经具备正式业务能力。

## 已确定的产品要求

- 产品名称为 **WorkX**。
- 以已打开的飞书工作台页面为视觉参考，提供高仿真交互原型。
- 支持在本机启动和访问。
- 界面仅支持简体中文和 English，首次使用默认中文，记住用户选择。
- 产品交付除 UI 外，还包含可供产品经理使用的功能清单。
- 生态接入支持持续扩展，飞书是其中一部分；后续将补充企业微信机器人相关的可接入 AI 能力。
- 生态配置采用“平台 → 接入方式 → 关联伙伴 → 授权能力”四步流程；飞书与企业微信分别配置，同一个智能伙伴可绑定多个平台及多个渠道。
- 每条绑定继续完成平台参数、授权步骤和连接测试，涵盖成功、失败修正、取消与重试；当前只验证本地交互，不接入真实平台。
- 机器人收到消息后，由绑定的智能伙伴执行任务，在工作台追踪进度和成果，并将结果回传来源会话；当前以本地模拟完整呈现流程及异常恢复。
- 后续梳理业务场景，并据此丰富工作台。具体场景、首批接入能力、方案和排期尚未确定。
- 团队协作围绕成员、多个智能伙伴、共享项目背景、任务分工和成果管理组织；界面预留业务场景入口。

当前功能范围依据代码整理；生态与业务场景规划依据已确定的产品方向。优先级、模块组织方式和后续版本划分为建议，尚未代表已经确认的研发排期。

## 生态与业务场景的产品结构

| 组成 | 承担的产品职责 | 与其他部分的关系 |
| --- | --- | --- |
| 工作台 | 提供场景入口、智能伙伴、任务进度、项目和成果的统一使用界面。 | 根据实际业务场景组织入口和待处理事项。 |
| 业务场景 | 明确谁在什么情况下解决什么问题，需要哪些输入，最终交付什么。 | 组合 AI 能力、企业工具和资料来源，沉淀可复用的任务模板。 |
| AI 能力与执行 | 提供模型、伙伴指令、工具调用、任务执行和成果生成。 | 由场景选择所需能力；执行状态和结果归入 WorkX 任务。 |
| 生态连接 | 接入飞书、企业微信及后续确定的企业工具，管理连接和可用能力。 | 按具体接入方式提供任务入口、资料来源或结果去向，并记录各自支持的范围。 |

同一业务场景可以按需组合多个生态的可用能力。机器人承担的交互或接入职责，与 AI 实际处理任务的能力分别记录；某一生态接入成功不代表全部功能都可以调用。

接入方案依据 [官方资料调研](ECOSYSTEM-INTEGRATION-RESEARCH.md) 区分对话渠道、通知出口和业务工具授权。原型以独立绑定记录保存平台、具体接入方式、关联伙伴和拟申请能力，同一伙伴可以有多个绑定；暂停、编辑或删除一个绑定不影响其他绑定。每个绑定只关联一个现有伙伴，伙伴的角色、指令和工作背景仍由 WorkX 管理。

“授权能力”是流程名称，当前只记录申请意向，不代表平台已授予权限。消息收发配置和业务数据访问申请分别展示；可选工具及其具体接口仍需真实接入时逐项验证。群 Webhook 仅作为原型中的通知输出方式，不提供接收对话、发起 AI 任务或业务工具授权的入口。跨平台身份、会话、资料权限不会因为绑定同一个伙伴而自动共享。

团队协作方向参考用户指定的 [扣子团队版说明](https://docs.coze.cn/about-coze-team)：多人共同参与、共同使用 Agent、共享项目上下文和统一管理资源。本轮将这些方向具体化为 WorkX 的团队空间、项目看板、共享背景和成员分工交互。真实多账号协作、资源权限、用量和本地 Agent 托管仍需后续建设。

| 规划对象 | 已确定方向 | 当前状态与待确认事项 |
| --- | --- | --- |
| 飞书生态 | 纳入 WorkX 生态，当前也作为界面视觉参考。 | 可分别选择“应用机器人”“群自定义机器人 Webhook”“业务 API 授权”，关联伙伴并记录拟申请能力；实际服务和授权待实现。 |
| 企业微信生态 | 补充智能机器人、应用消息和通知等接入方向。 | 可分别选择“智能机器人 API”“自建应用消息接入”“群机器人 Webhook”；智能机器人可记录 WebSocket 长连接或 HTTP 回调模式。实际输入输出、授权及可调用接口仍需验证。 |
| 业务场景 | 后续梳理并持续丰富工作台。 | 已预留入口，可创建、编辑和删除本地草稿；未预置具体业务场景。详细定义使用 [业务场景梳理模板](BUSINESS-SCENARIOS.md) 逐项记录。 |
| 其他企业工具 | 保留扩展空间。 | 具体工具按后续业务场景确定，暂不承诺接入清单。 |

## 状态和优先级

| 标识 | 含义 |
| --- | --- |
| 本地可用 | 浏览器内有实际操作和状态变化；标注为保存的业务数据保存在当前浏览器中。 |
| 交互模拟 | 可以体验流程，但内容、执行结果或连接状态来自预设逻辑。 |
| 待建设 | 当前没有对应的真实服务或完整功能。 |
| P0 | 建议作为首版可用产品的核心范围，保证发起任务到查看成果的完整流程。 |
| P1 | 建议在核心流程稳定后完善，提升日常管理和重复使用效率。 |
| P2 | 建议按用户需求验证结果投入的扩展能力。 |

“当前原型验收要点”描述现在可以验证的行为；后文“正式产品待建设项”描述上线真实服务前的新增要求，两者不能互相替代。

## SaaS 管理基础

产品按“租户／企业空间 → 组织部门 → 企业成员 → 角色与资源授权”设计。当前仅提供一个企业的本地管理原型，没有真实登录、多租户隔离或服务端鉴权。完整实体关系、角色矩阵、生态身份映射与首版验收要求见 [SaaS 基础产品设计](SAAS-FOUNDATION.md)。部门不自动授予资源权限，企业角色也不等于外部平台授权。

平台参数配置用于表达下一阶段真实集成需要的信息。飞书应用机器人及业务 API 使用应用凭证，应用访问 token 应由真实服务端获得并维护；群 Webhook 使用目标群提供的通知地址。企业微信智能机器人区分长连接和 HTTP 回调，自建应用使用企业和应用身份参数。连接测试只检验原型中的字段和步骤，并按用户所选情境演示结果，不能证明平台在线、凭据有效、事件可达或资料已授权。

## 正式产品待建设项

以下全部为“待建设”。首版先明确一个业务场景，再确定所需 AI 能力、资料来源、结果去向及接入生态。若该场景适合文字任务，可先支持一种真实文档成果；生态接入的顺序与范围随场景需求确定。

| --- | --- | --- | --- |
| RD-01 | 真实 AI 执行 | 任务实际使用所选伙伴的指令与上下文；接入至少一个可用模型；输出来自执行结果，能追踪任务与回答的对应关系。 | P0；承接 AG-03、TK-06 |

| RD-04 | 真实成果和追问 | 至少一种真实文档成果可预览和下载；追问使用已有任务上下文，结果可追溯到任务；复制内容与用户看到的回答一致。 | P0；依赖 RD-01、RD-03 |

| RD-07 | 项目和任务完整管理 | 支持修改项目、调整任务归属，以及明确的删除或归档规则；涉及项目成员时，补齐角色与可见范围。 | P1；依赖 RD-03、多人场景下的 RD-05 |
| RD-08 | 自动化调度 | 可编辑、暂停、删除计划；明确时区、下次运行和执行记录；到时产生真实任务，避免重复触发并能识别失败。 | P1；依赖 RD-01 至 RD-03 |
| RD-09 | 生态连接管理 | 将现有独立绑定配置接入真实平台，分别验证消息通道、通知投递和业务 API 状态；支持凭据安全存储、连接校验、授权撤销及断开。一个伙伴的多个绑定分别管理身份、会话和项目范围，任务可追溯到来源绑定；真实消息需验签、鉴权和去重，建立可恢复的任务与消息对应关系。 | 建议 P1；首个场景依赖的连接需进入首版，具体顺序待确定 |
| RD-10 | 可执行能力目录与伙伴发布 | 将拟申请能力映射到经过验证的接口、身份和数据范围，分别展示待授权、已授权和失效状态；工具调用有结果与错误信息。消息接入成功不自动授予业务工具权限，权限变更需重新校验；第三方伙伴具备来源、配置和停用机制。 | P1；依赖 RD-01、RD-05、所需生态连接 |
| RD-11 | 多格式成果 | 真实生成并验证 PPTX、XLSX、DOCX 等文件，预览和下载类型一致；如扩展在线编辑，再设计版本和冲突规则。 | P1；依赖 RD-04 |
| RD-12 | 小队和编程工作区 | 小队具备成员、分工与汇总；编程入口可连接工作项目、执行任务并审阅代码变更。两者应分别立项，不能以现有标签或入口视为完成。 | P2；依赖真实执行与工具能力 |
| RD-13 | 真实语音与主动帮助 | 语音支持采集、转写和失败反馈；主动帮助具备明确触发条件、来源、频率及关闭机制。 | P2；先验证用户使用需求 |
| RD-14 | 真实通知与结果回传 | 真实任务与自动化事件生成可追溯通知；结果按场景配置进入工作台或已验证支持的外部渠道；回传失败可识别，保留原任务和成果；按原会话投递并记录平台回执，重试不重复执行任务，平台重放和重复回执不重复投递。 | P1；依赖真实执行和对应连接能力 |
| RD-15 | 真实企业微信机器人接入 | 按选定的智能机器人 API 模式或自建应用消息方案联调，群 Webhook 单独验证通知出口；逐项确认输入、输出、身份、触发方式与授权条件。能力可供场景调用，任务来源与结果去向可追溯；不自动包含个人微信。 | 接入方向已确定；具体版本与优先级随场景和选型确认 |
| RD-16 | 可执行场景模板 | 将已确认的场景草稿扩展为明确输入、步骤、AI 能力、生态依赖、成果及成功标准的模板；模板能发起真实任务，未配置或未支持的能力明确显示。 | 首批场景梳理建议 P0；功能建设范围按场景确认 |
| RD-17 | 场景化工作台 | 在现有预留入口基础上展示已确认场景的快捷入口、相关任务、待处理事项和成果，逐步扩展。 | 首批实际场景入口建议 P0，持续丰富为 P1；依赖 RD-16 |
| RD-18 | 真实团队协作与资源同步 | 成员用独立账号参与同一项目，共享授权范围内的背景、任务和成果；分工与确认跨端同步，处理并发更新和成员变更。 | P0；依赖 RD-03、RD-05 |
| RD-19 | 团队用量管理 | 管理者可查看真实任务及模型调用用量、归属和时间范围；统计来源可核对，不以演示计数替代真实消耗。 | P1；依赖真实执行与账号权限 |
| RD-20 | 外部与本地 Agent 托管 | 根据实际业务确定需接入的 Agent、连接方式、设备权限与任务生命周期；状态、调用结果及失联情况可追踪。 | P2；先确认接入方案和业务需求 |

## 核心流程验收

这些场景可直接转为原型走查用例。正式产品还需同时满足上一节对应的真实服务标准。

| 场景 | 操作步骤 | 当前版本应看到的结果 |
| --- | --- | --- |
| 新用户开始任务 | 首次打开 → 使用中文界面 → 选择伙伴 → 输入目标 → 发送 | 创建任务，先展示运行中，再出现标注为演示的回答；任务出现在列表。 |
| 自定义伙伴 | 新建伙伴 → 编辑基本信息、指令和工作背景 → 刷新 → 发起任务 | 已保存信息仍可查看；任务归属正确；不能据此认定自定义指令已参与模型执行。 |
| 项目内完成任务 | 新建项目 → 从项目发起任务 → 查看回答 → 打开成果 → 回到项目 | 任务关联正确；成果可文本预览和下载 `.md`；项目任务数同步变化。 |
| 整理历史任务 | 重命名 → 置顶 → 归档 → 筛选已归档 → 恢复 | 名称更新且保存，侧栏置顶排序生效，归档后隐藏，恢复后重新出现。 |
| 查看交付成果 | 进入文件库 → 按类型筛选 → 打开文件 → 下载 | 筛选范围正确；详情为文本预览；即使是演示文稿或表格示例，当前下载仍为 `.md`。 |
| 配置自动化 | 创建周期任务 → 设置频率和时间 → 暂停 → 刷新 → 恢复 | 配置及状态保留；当前不会实际到时执行，不能用此场景验收调度服务。 |
| 切换语言 | 输入普通或编程任务草稿并选项目 → 切换 English → 再切中文 → 刷新 | 切换语言时保留草稿与选择；界面语言正确并在刷新后保留；用户文本不被翻译。刷新会清空尚未提交的草稿和临时选择。 |
| 团队共同推进项目 | 添加演示成员 → 选择共享伙伴 → 在项目管理成员与伙伴 → 编辑背景 → 为任务分工 → 确认成果 → 查看协作动态 | 本地成员、分工、背景和确认状态保留；看板和动态更新；没有真实邀请、多人同步或多 Agent 执行。 |
| 四步生态配置 | 打开生态接入 → 选择飞书 → 选择应用机器人 → 关联已有伙伴 → 命名并选择能力 → 保存 → 进入接入配置 | 绑定按平台、方式、伙伴、申请能力展示；接入参数另行配置，状态仍为本地演示及待真实授权；不发生外部通信。 |
| 同一伙伴跨平台绑定 | 为同一伙伴新增飞书绑定和企业微信绑定 → 编辑其中一条 → 暂停并恢复其中一条 → 删除其中一条 | 两条记录及其状态独立；操作不覆盖另一条记录，也不改变伙伴本身；刷新后保持结果。 |
| 方式与能力限制 | 在向导中从机器人切换到群 Webhook，再切到业务 API 或其他方式 | 清除不兼容项、保留兼容项并补齐必选项；群 Webhook 仅通知输出，无对话、工具授权或对话任务入口。飞书业务 API 未选工具时不能完成保存；工具申请不代表消息权限或真实授权。 |
| 编辑与取消 | 打开已有绑定 → 修改名称、方式和能力 → 返回前一步 → 取消；再次打开并保存修改 | 返回时保留当前草稿；取消不改变原记录；明确保存后才更新对应绑定。删除确认中取消也不会改变记录。 |
| 伙伴详情绑定范围 | 打开一个伙伴详情 → 查看生态绑定 → 新增绑定 → 回到生态接入页 | 详情只列出当前伙伴的记录；新增预选当前伙伴；完整生态页仍能管理其他伙伴的绑定。 |
| 绑定用途预览 | 分别预览机器人、群 Webhook 和业务 API 绑定，暂停后再次查看 | 路径与接入用途一致，区分双向对话、结果通知和工具调用；状态不被描述为真实已连接或已授权。 |
| 生态配置兼容 | 使用旧版保存的名称与暂停配置 → 打开新版 → 补充待确认方式 → 删除迁移记录 → 刷新 | 已有名称、伙伴与暂停状态保留；不确定方式需要补充；迁移不产生未经选择的新授权能力；已删除记录不会由旧字段重建。 |
| 向导中切换语言 | 填写生态绑定名称并选择方式、伙伴和能力 → 切换 English → 再切回中文 | 当前步骤和草稿内容保留，选择对应关系不变；用户名称不自动翻译，双语提示均明确待真实授权。 |
| 平台参数配置 | 从绑定进入接入配置 → 切换支持的消息连接方式 → 留空必填项并继续 → 填入示例参数 → 下一步 | 字段随平台、接入形态和传输方式变化；缺失或格式错误就地提示；飞书长连接不要求回调地址，Webhook 不展示消息接收和应用凭证。 |
| 授权步骤核对 | 参数校验通过 → 查看本方式授权清单 → 漏选一项后继续 → 补齐确认 | 未完成步骤有提示；各平台指引明确区分事件、权限、发布和群设置；勾选只表示本地确认，能力仍待真实授权。 |
| 模拟成功与取消 | 完成参数和授权清单 → 选择模拟成功 → 开始测试 → 观察进度；另一次在运行时取消 | 成功标注模拟，不变成真实已连接；取消后不再由旧计时回调跳到成功，不保存未完成测试。 |
| 失败与重试 | 分别选择凭证错误、权限缺失和超时 → 运行 → 按建议修正或重试 | 结果和修正步骤对应；修改参数或授权确认会清除旧测试，修正后可重新运行；不产生真实平台请求或测试消息。 |
| 保存与敏感参数清除 | 完成模拟测试 → 保存 → 重开配置 → 刷新；另一次填写后关闭而不保存 | 已保存非敏感配置、确认项和模拟结果可查看；Secret、Token、AES、签名密钥和完整 Webhook URL 不留存在存储中，重测需重填；取消不覆盖旧配置。 |
| 配置变更使测试失效 | 测试后修改参数或授权项；再修改绑定方式、传输方式、伙伴或能力，最后仅修改名称或暂停状态 | 影响接入的变更清除测试或重置接入配置；名称与启停变化保留配置；另一个平台或伙伴绑定不受影响。 |
| 接入面板中切换语言 | 填写参数或勾选授权清单 → 在面板中切换 English → 回到中文 | 当前阶段、填写值与选择保留，用户值不被翻译；敏感值仍只在当前弹窗会话中，关闭后清除。 |
| 平台消息进入任务 | 准备已启用且模拟连接成功的双向绑定 → 打开消息工作台 → 填写消息 → 关联项目并提交 | 由绑定伙伴创建一条任务；工作台、详情和项目中的来源及进度一致，不发真实平台请求。 |
| 群触发与入口限制 | 尝试群聊未 @、自建应用群聊、暂停绑定、Webhook 或业务 API | 不创建不符合当前触发规则的任务；告知需要修正的条件；不存在通知入口伪装为聊天入口的情况。 |
| 成功与结果回传 | 选择成功情境提交 → 观察执行 → 查看成果 → 查看回传 | 成果关联原任务并进入资料库，回传状态单独变化，目标始终是原始平台绑定与来源会话；记录明确为模拟。 |
| 执行失败重试 | 选择执行失败 → 查看错误 → 重试执行 | 继续原任务并保留来源，不新增第二条任务；成功后生成成果并进入回传流程。 |
| 回传失败重试 | 选择回传失败 → 确认成果已生成 → 重试回传 | 不重复执行伙伴、不重复生成成果，只更新原结果的回传过程；任务完成与回传失败可同时存在。 |
| 同伙伴跨平台 | 用同一伙伴的飞书和企业微信绑定分别提交不同会话消息 | 任务、原始消息、项目、成果及回传目标可逐条对应，不混用会话或改投另一平台。 |
| 运行期间变更绑定 | 发起消息任务后暂停、删除或修改来源绑定 → 等待回传或重试 | 检查当前绑定条件，明确阻断无效投递；旧计时回调不能把结果发送到新身份或错误会话。 |
| 重放与取消 | 在任务详情重放消息 → 核对任务与成果数量；另一次在执行或回传中取消 → 等待原计时结束 | 重放记录可见但无重复任务或成果；取消后不被旧回调推进为成功；已有成果保留，可按对应阶段重试。 |
| 刷新中断流程 | 执行或回传期间刷新 → 查看任务详情 → 按提示恢复 | 未完成阶段标记中断，不自动假定成功；已有成果保留，恢复回传不重复生成成果。 |
| 记录业务场景 | 打开场景入口 → 创建草稿 → 编辑 → 刷新 → 发起删除并取消或确认 | 草稿保留用户内容；删除需要明确确认；不会自动生成业务任务或可执行模板。 |
